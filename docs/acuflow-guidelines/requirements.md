# AcuFlow 需求原文（急腹症全流程人机协同决策系统）

> 来源：`docs/` 内原始 `.docx` 文档转换。仅作内容保存，原始文件保留。

## 标题

基于时序多模态证据与安全约束的急腹症全流程人机协同决策系统：开发、外部验证与前瞻性临床评价

## 1. 总目标

对成人非创伤性急腹痛患者，持续整合当前可获得的临床信息，辅助医生完成危险识别、鉴别诊断、下一步检查选择、治疗安全审核、动态复评及去向决策，并保留完整证据和操作记录。

## 2. 初始目标

一个能够自动整理病例、发现重要遗漏和证据冲突、追踪复评及待完成事项的院内助手。

初始目标特点：**诊断广覆盖，治疗窄范围。**

- 诊断广覆盖：不仅覆盖普外科，也需识别妇产科、泌尿外科、心内科、血管外科需要紧急处理的患者，不漏重大危急疾病。
- 治疗窄范围：初期只深入支持少数成熟路径（阑尾炎、胆道感染、胰腺炎、肠梗阻）；妊娠、创伤等先保留识别和转诊提示，不直接套用普通成人治疗路径。

## 3. 理论上流程模式

流程特点：**评估 → 行动建议 → 医生确认 → 实际执行 → 结果回流 → 再评估**

| 诊疗节点 | 系统抓取特征 | 返回辅助结果 |
|---|---|---|
| 分诊、首次接诊 | 主诉、起病时间、生命体征、意识、重点病史 | 是否需要立即床旁评估；有哪些不能等待资料齐全的危险信号 |
| 问诊、查体完成 | 症状特点、腹部体征、既往手术、用药、过敏、妊娠可能性等 | 关键遗漏；主要鉴别诊断；有目的的检查检验建议 |
| 第一批检验返回 | 原始数值、单位、参考范围、标本信息 | 哪些结果改变风险或诊断；哪些异常需要核实；哪些检查仍缺失 |
| 影像及会诊结果返回 | 影像报告、经验证的影像分析结果、会诊意见 | 临床与影像是否一致；诊断、严重程度和处理方式是否需调整 |
| 治疗、留观期间 | 实际给药、补液、引流、疼痛变化、生命体征和复查趋势 | 是否达到预期；是否出现恶化或治疗失败信号；哪些事项尚未执行 |
| 住院、转院、出院前 | 最新状态、未解决问题、待回报结果、随访条件 | 去向建议的依据与限制；仍未排除的危险问题；交接和复诊提醒 |

## 4. 理论数据清单

| 数据层 | 覆盖内容 | 优先级 |
|---|---|---|
| 基础和既往信息 | 年龄、体重、既往腹部手术、基础疾病、肝肾功能基线、近期住院、肿瘤及免疫抑制状态 | 第一阶段 |
| 用药和过敏 | 当前及近期药物、抗凝抗血小板药、激素、抗菌药、过敏类型与严重程度 | 第一阶段 |
| 病史与查体 | 起病时间、疼痛部位及迁移、性质、排气排便、呕吐、出血、黄疸、尿路症状、月经与妊娠信息、腹膜刺激征等 | 第一阶段 |
| 生命体征与护理记录 | 血压、心率、呼吸、体温、血氧、意识、疼痛、出入量、胃管及引流情况、反复查体 | 第一阶段，尤其重视连续变化 |
| 检验 | 血常规、生化、肝胆胰指标、凝血、血气及乳酸、尿液、妊娠相关检验、微生物等；仅纳入临床有指征者 | 第一阶段 |
| 影像报告 | 超声、CT、MRI 等的检查方式、所见、结论、限制条件、与既往比较 | 第一阶段 |
| 原始影像 | 完整 DICOM、增强期相、层厚、覆盖范围；超声动态图像和多普勒信息 | 后续独立模块 |
| 治疗与反应 | 医嘱是否真正执行，给药剂量与时点，补液量，减压、引流、手术及其后变化 | 第一阶段开始记录，后续重点建模 |
| 其他专业资料 | 心电图、相关专科意见、外院资料、既往相关影像 | 按适应证接入 |
| 结局与反馈 | 最终诊断、手术所见、病理、培养、并发症、复诊、再入院、ICU 及死亡 | 从开始就采集，但不能提前泄漏给模型 |
| 医院可执行条件 | 夜间 CT、ERCP、介入、手术室、ICU、转诊资源及实际等待情况 | 第二阶段开始 |

理论数据特点：

1. 保留数据实际采集和返回时间以及版本信息。
2. 区分未采集数据和阴性数据。
3. 重要判断要返回原始证据。

## 5. 初始任务三步走

1. 先使用线上 ChatGPT 制定固定流程。
2. 自行训练部署本地模型 + 影像预训练模型，多模态制定固定流程。
3. 可适当蒸馏提取小型医用专用模型，提高能力，减少部署资源消耗。
